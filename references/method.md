# 断言拆解与证据绑定方法

版本：1.0.0。适用于科研材料中结论的原子化、逐条证据核验和 JSON 导出。字段定义以 `schema.md` 为准；本文件说明人工或 Agent 必须做出的语义判断。

## 先确定任务边界

读取真实的 `case.json`、`task.md` 和实际材料；以它们的任务、输出合同和证据范围为准。论文标题、目录名、挑战的领域标签只能帮助导航，不能替代正文证据。先列出待回答要求及可用材料，不把训练例子或本文中的合成数字带入案例。

记录各个要求的覆盖情况：`covered`、`partial`、`not_reported`、`cannot_determine`、`material_missing` 或 `execution_failure`。其中，`not_reported` 表示在可访问且已检查的指定范围中没有报告；`material_missing` 表示需要的材料未提供；`cannot_determine` 表示现有证据不能决定答案；`execution_failure` 表示工具执行失败。这些状态不能互相替代。

## 原子断言判据

一条断言表达一个可独立判断真假的命题：同一主体、同一主要关系、同一对象或比较终点，并带上决定其真值的条件。多个终点、多个独立人群、多个时间点或独立事实通常拆开；数值与它所属的终点保留在一起。

拆解时执行三项检查：

1. **独立反证检查**：若句子一半可以为真而另一半为假，通常要拆成两条。
2. **限定词删除检查**：删除条件、比较基线、样本、人群、测量时间、单位、统计措辞或版本会改变结论范围时，把这些信息保留在 `qualifiers`。
3. **主体替换检查**：方法、干预、受试者、数据集与作者的解释不是同一主体；代词必须回指到实际对象。

保留否定与不确定性。“未检测到差异”不能改写为“完全相等”，“相关”不能变成“导致”，“作者推测”不能变成“已证实”。不要将整段摘要当成一条断言，也不要把同一测量的数值、单位、比较对象拆成无法独立解释的碎片。

`review.atomic`、`review.scope_checked` 和 `review.entailment` 是实际语义复核的记录。只有完成检查后才填入相应判断；脚本无法证明这些布尔值或解释文字是真实的。

## 关系受控词表

优先选最保守且忠实于证据的关系。关系方向按 `subject -> relation -> object` 解释。

| relation | 适用含义 | 常见误用 |
| --- | --- | --- |
| `reports` | 来源报告一个结果或描述性事实 | 用它掩盖可明确表达的方向性关系 |
| `compares` | 明确进行一项比较 | 把“进行了比较”当成“比较有显著差异” |
| `associated_with` | 观察性相关、关联 | 改写成因果 |
| `increases` / `decreases` | 某个量相对基线上升或下降 | 忽略基线、单位、人群、时间 |
| `no_detected_difference` | 研究未检测到差异 | 宣称两者等效或数值完全相同 |
| `causes` | 原文及研究设计支持所述因果范围 | 仅凭相关性、模型预测或作者推测选用 |
| `improves` / `worsens` | 有明确评价方向的改善或恶化 | 将数值变大自动理解为改善 |
| `measures` | 方法或工具测量某对象 | 混淆测量值与真实物理量 |
| `uses` | 方法、研究使用数据、设备或资源 | 将所用材料当成结论来源 |
| `predicts` | 模型作预测，限定评价设置 | 把预测当成实际发生或因果 |
| `supports` / `contradicts` | 一项结果对另一明确命题的支持或冲突 | 混同证据链接的 `role` 字段 |
| `other` | 以上词均不能忠实表达 | 忘填可理解的 `relation_label` |

`polarity` 单独记录正向、否定或不确定命题。否定命题仍可能被直接证据支持；`support` 描述的是证据关系，不能机械地由 `polarity` 推导。

## 最小充分证据

先从真实材料建立 `corpus.json`，再使用 `locate` 或直接查看分段文本定位。为每条断言选择能支持其主体、关系、对象和关键限定词的最短充分证据；仅包含关键词的短语不构成充分证据。

每个证据记录通过 `source_id + segment_id + start + end` 定位；区间从 0 开始，按 Unicode 字符计数，左闭右开。`quote` 必须与 `segment.text[start:end]` 完全一致。不要为了匹配而改字、压缩空白、补充省略号或把译文当成原文引文。拆成多个证据条目可以表达跨段或跨页支持。页码是文件页序；印刷页码或图表编号应另作语义说明，不能互换。

页码、段号和偏移使人能回到提取文本；它们本身不保证多栏顺序、表格归属、上下标和公式正确。对这类材料还需回看原 PDF/图表。当提取顺序错误、文本残缺、扫描页无文本、单靠图形才能解读或不同解析器结果冲突时，明确记录限制，不把不完整片段当成可靠证据。OCR 结果须与图像复核，不能将 OCR 猜字当作原文。

证据角色使用 `supports`、`contradicts` 或 `context`：上下文不能单独支撑断言；直接证据与反证不能丢弃任何一方。若原文写的是作者引用其他工作的结论，绑定到当前文档只证明“当前文档报告该说法”。若任务要求验证被引原论文，必须实际取得并检查被引来源，否则标明未核验。

## 直接证据、推论与冲突

- `direct`：原文明确表达同一命题，且限定范围一致。
- `inferred`：经过计算或多片段推导才能得到。填写 `derivation`，说明输入证据、计算或逻辑步骤、假设及适用范围。不得将这种推论写成作者原话。
- `contradicted`：可访问证据与候选命题冲突。保留候选及反证并说明冲突，不能输出成已证实事实。
- `insufficient`：缺少必要支持、关键限定词缺失或证据只能提供上下文。不要靠常识补全。

遇到版本或材料间冲突，首先核对人群、终点、单位、时间、版本和方法是否一致。条件不同的结论可同时成立；条件相同而数字不同则保留两套来源及差异。未获得纠错或更正依据时，不擅自宣布某一版本正确。

## 来源与标识

以实际文件哈希标识本次读取的字节版本。标题、作者、年份、DOI、版本只从所提供材料的显式位置或授权访问的来源获取，并用 `metadata_evidence` 指向相应证据。缺失字段使用 `null` 或空列表并说明，不从文件名推断出版年份，不生成看似真实的 DOI。文件路径是本次运行的位置，不等于公开可访问的学术标识。

不要跨版本无条件去重。相同来源中主体、关系、对象及限定词完全一致的重复断言可以合并，并保留所有证据；数值、人群、时间、终点、版本或否定性不同的断言不能以“相似”为由合并。标识符用于本次结果中的稳定引用，不宣称全球可解析或加密可验证。

## 置信度与复核

`confidence.level` 是透明的定性判断，不是校准过的概率。`basis` 必须写出可检查的理由，例如“正文直接报告同一比较和单位；表2方向一致；未见该终点的区间估计”，而不是“模型认为可信”。

- `high`：清晰的直接证据，关键条件可核对，未发现相关冲突。
- `medium`：明确标注的推论，或存在可描述但不推翻核心命题的限制。
- `low`：支持弱、图表/解析存在未解决疑点、材料冲突。
- `undetermined`：没有足以判断该命题的材料。

脚本检查字段、引用和精确定位，不能判断科研结论是否成立，也不能替代逐条语义复核。通过 `verify` 只说明自动检查未发现它所覆盖的问题，不能称为“科研事实已验证”。

## 导出与边界

平台实际 `output_contract` 优先于本地推荐结构。将正式要求的字段及值写入 `candidate.contract_result`；保留输入的 `case_id`，不要把未知答案用空字符串冒充完成。`finalize --case ...` 用于检查与保存正式结果，同时单独保存规范化断言和验证记录。遇到不支持的合同形态时回到实际合同逐项处理，不自行发明正式字段。

这个 Skill 交付的是带证据链接的 JSON 知识单元。它不自动生成符合正式 Nanopublication RDF 规范的命名图、可信 URI、数字签名或发布记录。若任务明确要求这些格式，应按实际合同扩展并验证，而不是将当前 JSON 标称为已签名的标准 Nanopublication。

正式固定案例和公平对照由平台提供。教学例子、本地脚本测试、格式检查均不能代替平台结果，不能据此宣称准确率、节省比例或比赛分数。
